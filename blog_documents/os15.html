Part XV: User Space

What are we making

Now that processes are fully made, we want to take our processes and make it possible for them to run outside of the kernel. While this section is pretty distinct from tasking, we are still building directly on top of it, and we will be editing the infrastructure for our tasking. This section on making the user space is also split up into it's own two parts:

  • Userspace: We get processes to run safely outside of the kernel
  • System calls: We allow user space processes to request services from the kernel
On x86 32 bit architecture, the cpu has 4 levels of privalege, but for our OS we are only really using 2, these being Ring 0 privilege (for kernel stuff) and and Ring 3 (for usermode stuff).

We know what ring we are in via the CPL (Current privilege level). This is set from the currently loaded code segment, the CPL is the bottom 2 bits of the CS selector.
So now we currently have: 

GDT
├── gdt_null
├── gdt_code
└── gdt_data

And next we will have: 

GDT
├── gdt_null
├── gdt_code
├── gdt_data
├── gdt_user_code
└── gdt_user_data

With the user data and code segments having their appropriate flags. The privilege level is stored inside the GDT descriptor if you remember correctly when we made our GDT. So how we set our ring level is by changing which GDT descriptor is loaded into CS

Rings are NOT enough

If we set the ring level, our memory is still not completely protective, this is becuase we also need to set priveleges within the page tables. As in our OS we have flags for present, writable and user. This is where we will have to change the existing VMM, as we need to make a way to set the USER flag for when we want to make a page for user mode.

Each user process will have it's own page directory, this is becuase for each process we will probably have the same start address for each program, for example 0x00400000 we want a constant address to mark the start but will actually reference different locations in physical memory.

As well as changing the GDT and paging, we need ot do a couple of other changes in order to make our architecture:

  • Changing processes so that each user one gets it's own page directory
  • Giving each process it's own user stack in it's user address space
  • Needs a safe to execute kernel stack in rder to temporarily enter the kernel when it needs to
We also need to know about TSS (Task State Segment). This is a CPU-defined structure that tells the CPU which kernel stack we should use if we go from ring 0 to ring 3.

Ring 3 Execution

We can't just call user functions, the perfect place to change things like CS in order to enter a user process is the scheduler that we have made before, so we will also have to edit this aswell.

This is all we need to know to make user space for now, it includes refactoring of alot of our previous code, and really we could have been implementing the user space parts from the very start, but it would have taken until this stage in order to actually get user space processes working, as we would still need to implement system calls after this.
